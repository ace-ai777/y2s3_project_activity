# y2s3_project_activity
Консольная C++ программа для имитационного моделирования распространения информации в виртуальном сообществе из 200 пользователей. Учебный проект.

Правила работы с репозиторием (Workflow)
На этапе инициализации проекта (создания структуры файлов и каркасов функций) коммиты в ветку `main` вносились напрямую администратором. Это было необходимо для быстрой настройки "скелета" проекта. Однако, для дальнейшей командной разработки такая практика не является приемлемой. Поэтому с текущего момента (31.10.2026) в репозитории действует строгое правило:

1. Прямые пуши в ветку `main` запрещены для всех.
2. Для добавления любого кода или документации необходимо создать отдельную ветку (`feature/...`, `docs/...`), внести изменения, запушить их и создать Pull Request.
3. Только после проверки и слияния PR (Merge) код попадает в `main`.

Технически это ограничение закреплено с помощью Ruleset под названием "No_pushes_to_main" в настройках репозитория. Оно блокирует любые прямые пуши и force-push в главную ветку, мотивируя команду соблюдать процесс добавления кода через Pull Requests.
